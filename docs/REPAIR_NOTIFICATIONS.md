# การแจ้งเตือนงานซ่อม (LINE / SMS)

เอกสารนี้ตอบ QA ข้อ 06 (รอบ 7 พ.ย. 2569) ว่าระบบส่งข้อความอะไร เมื่อไร และไปที่ไหน

## ช่องทางที่มี

| ช่องทาง | สถานะ |
|---|---|
| LINE ผ่าน LINE Portal | ใช้งานอยู่ ต้องตั้ง `LINE_PORTAL_NOTIFY_URL` และ `LINE_PORTAL_API_TOKEN` |
| SMS | **ยังไม่มีในระบบ** ต้องเลือกผู้ให้บริการ SMS ก่อน |

ระบบส่ง LINE ผ่าน LINE Portal ซึ่งเป็นบริการภายนอก ไม่ได้ส่งเข้า LINE ของลูกค้าโดยตรง Portal ส่งข้อความไปยังปลายทางเดียวที่ตั้งไว้ในฝั่ง Portal (เช่น กลุ่ม LINE ของร้าน) เพราะคำขอที่ระบบส่งไม่ได้ระบุผู้รับ

## ข้อความถูกส่งเมื่อไร

| เหตุการณ์ | ส่งเมื่อ | ข้อความแสดงสถานะ |
|---|---|---|
| เปลี่ยนสถานะงานจากหน้าใบงาน (admin) | ทันทีที่บันทึกสถานะใหม่สำเร็จ ทุกสถานะ | ชื่อสถานะใหม่ |
| เสนอราคา | เมื่อเปลี่ยนเป็น "เสนอราคาแล้ว" หรือ "รออนุมัติ" | "เสนอราคาแล้ว" / "รออนุมัติ" |
| ซ่อมเสร็จ | เมื่อเปลี่ยนเป็น "ซ่อมเสร็จ/รอรับคืน" | "ซ่อมเสร็จ/รอรับคืน" (หรือ "ไม่ซ่อม/รอรับเครื่องคืน" ถ้าลูกค้าปฏิเสธ) |
| ส่งมอบเครื่องและปิดงาน | เมื่อบันทึกการส่งมอบสำเร็จ | "รับเครื่องคืนแล้ว" |

ไม่ส่งในกรณีต่อไปนี้:
- สถานะที่เปลี่ยนมาจาก Web POS ผ่าน Integration API
- การบันทึกราคาโดยไม่เปลี่ยนสถานะ
- การรับเงิน การบันทึก QC และการส่งเครื่องไปร้านซ่อมภายนอก

## เนื้อหาในข้อความ

ข้อความ LINE (Flex) มีข้อมูลต่อไปนี้:
- เลขที่งาน (Job ID) และเครื่อง (แบรนด์/รุ่น)
- ชื่อลูกค้า เบอร์โทร และ LINE ID (ถ้ามีบันทึกไว้) ส่วนงานเครื่องของร้านแสดงว่า "เครื่องของร้าน"
- สาขารับงาน
- สถานะใหม่
- ปุ่ม "เปิดใบงาน (พนักงาน)" ไปหน้าใบงานในระบบ admin (ต้องล็อกอินพนักงาน ลูกค้าเปิดไม่ได้)
- ปุ่ม "โทรหาลูกค้า" (เมื่อมีเบอร์โทร)

ข้อความสำรอง (altText ที่แสดงในรายการแชต) มี Job ID สถานะ ชื่อ และเบอร์โทรลูกค้า

## ส่งถึงลูกค้ารายคน

ตอนนี้ Portal รับเฉพาะ `{ messages }` ถ้าฝั่ง Portal รองรับการส่งรายคนแล้ว ให้ตั้งค่า `LINE_PORTAL_SEND_RECIPIENT=true` ระบบจะส่งข้อมูลผู้รับแบบอ่านได้ด้วยเครื่องไปพร้อมข้อความ:

```json
{
  "recipient": {
    "event": "repair_status_changed",
    "jobId": "JOB2611-0004",
    "status": "ready_pickup",
    "statusLabel": "ซ่อมเสร็จ/รอรับคืน",
    "branch": "น้ำยืน",
    "customer": { "customerId": "CUS00004", "name": "…", "phone": "…", "lineId": "…" },
    "adminUrl": "https://naravichcare.com/admin/repair/jobs/<id>"
  },
  "messages": [ … ]
}
```

ข้อจำกัด:
- การ push LINE ถึงลูกค้ารายคนต้องใช้ LINE userId ของลูกค้า ซึ่งได้มาเมื่อลูกค้าเพิ่มเพื่อน LINE OA ของร้าน
- LINE ID ที่พนักงานพิมพ์ไว้ใช้ส่งข้อความโดยตรงไม่ได้

## วิธีตรวจ (QA)

1. ตั้งค่า LINE Portal ให้ส่งเข้ากลุ่มหรือบัญชีของทีมทดสอบ
2. เปิดงานใหม่ที่ลูกค้าทดสอบมีเบอร์โทรและ LINE ID
3. เปลี่ยนสถานะตามลำดับ: เสนอราคาแล้ว → รออนุมัติ → (บันทึกอนุมัติ) → กำลังซ่อม → ตรวจสอบงานซ่อม → (QC ผ่าน) → ซ่อมเสร็จ/รอรับคืน → ส่งมอบ
4. แต่ละขั้นต้องได้ 1 ข้อความที่มี Job ID ชื่อ/เบอร์ลูกค้า และสถานะตรงกับขั้นนั้น
5. ถ้าไม่ได้รับข้อความ ให้ดู log ของเซิร์ฟเวอร์ (pm2) ว่ามี `LINE Portal rejected` หรือ `LINE Portal is not configured` หรือไม่
